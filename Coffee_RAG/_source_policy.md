# 來源與查證規則

## 原則

- 寧可標記待補，也不要編造來源。
- 穩定常識可以先做草稿，但不能標記為 `ready`。
- 涉及最新資訊時必須查證。

## 必須查證的內容

- 價格、租金、成本。
- 法規、稅務、食品安全規範。
- 平台規則。
- 設備型號、規格、上市資訊。
- 產品庫存、供貨狀態、包裝規格。
- 咖啡比賽結果。
- 最新市場趨勢。
- 品牌或公司現況。

## 產品知識來源

- 產品頁、庫存頁、型錄、報價單、供應商訊息都可以作為來源。
- 庫存狀態不視為穩定知識；回答使用者前必須重新查證或標示查詢日期。
- 若來源頁以 `x`、空白或其他符號表示庫存，必須先確認符號定義，不能自行解讀。

## 外部文章來源

- 部落格、媒體文章、報告、影片逐字稿可先登錄到 `00_來源資料/`。
- 來源登錄只記錄 metadata、摘要、拆分方向，不整篇搬運原文。
- 轉成正式知識文章時，必須用自己的結構重寫，並保留原始來源連結。
- 趨勢、價格、市場預測、品牌現況屬於會變動資訊，回答前需重新查證。

## 證據層級

- Tier A：官方組織、研究機構、標準文件、同行評審論文。用於科學、標準、評鑑、感官詞彙與方法論。
- Tier B：專業媒體、產業新聞、專家長文。用於趨勢、商業脈絡、文化與案例。
- Tier C：品牌部落格、咖啡學院、產品頁。用於教學語彙、產品命名、案例與在地表述。
- Tier D：社群、論壇、未查證摘要。只能作為問題線索或顧客語言，不作正式知識來源。

正式文章應優先使用最高可得層級。若只能使用 Tier C 或 Tier D，必須明確標記限制。

## 來源格式

在 frontmatter：

```yaml
sources:
  - type: web
    title:
    url:
    accessed:
```

書籍：

```yaml
sources:
  - type: book
    title:
    author:
    publisher:
    year:
```

訪談或內部資料：

```yaml
sources:
  - type: internal
    title:
    owner:
    date:
```

## 來源段落

文章底部的 `## 來源` 要用人看得懂的格式列出來源。沒有來源時寫：

```md
待補
```
