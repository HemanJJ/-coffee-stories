# Markdown 寫作規範

## 語氣

- 使用繁體中文。
- 語氣清楚、直接、可教學。
- 避免過度行銷或過度詩意。
- 可以保留專業詞，但第一次出現時要解釋。

## 結構

- 每篇文章只有一個 `# H1`。
- 用 `##` 拆出穩定段落。
- 不使用太深的標題層級，最多到 `###`。
- 清單每點只講一件事。

## RAG 友善寫法

- 每個段落離開全文後仍要大致可理解。
- 定義、流程、比較、注意事項分開寫。
- 關鍵詞與同義詞放在 `tags` 或「相關概念」。
- 不用「本文」、「上面」、「下面」作為主要指代。

## 內容深度

草稿階段：

- 可以先列出定義、重點、待補來源。
- 不需要一次寫成百科。

可發布階段：

- 補來源。
- 補內部連結。
- 移除待確認文字。

RAG-ready 階段：

- 段落清楚。
- 同義詞齊全。
- 沒有失效連結。
- 問答可以直接引用文章內容回答。

## 檢查清單

完成每篇文章前檢查：

- [ ] frontmatter 完整。
- [ ] `title` 與 H1 一致。
- [ ] `category` 與所在資料夾一致。
- [ ] `status` 合理。
- [ ] 有摘要或短答。
- [ ] 有內部連結或註明待補。
- [ ] 有來源或註明待補。
